# The AI Riemann hypothesis proof is almost certainly true, independent mathematicians attest

Scientific American · Clara Moskowitz · 2026-11-20

Mathematicians are now almost certain the earth-shattering artificial-intelligence-created proof of the Riemann hypothesis is real.
This morning Anthropic mathematician Levent Alpöge claimed to have used the company’s Claude AI model to solve the Riemann problem, perhaps the most important open quandary in mathematics. The hypothesis, first posed in 1859 by mathematician Bernhard Riemann, suggests that a hidden pattern underlies the distribution of the prime numbers—those numbers that are divisible only by themselves and 1.

Now researchers have verified that the proof does seem to do what Alpöge claims. Alpöge initially checked the work by writing out the proof using the programming language Lean; if a Lean-coded proof compiles error-free, this is usually taken as confirmation that the logic and math in each step is correct.
But some questions remained. For instance, does the proof really address the Riemann hypothesis, or does it establish a subtly different point or idea? “The first question which one has to ask when judging a PDF which comes with some Lean code is: ‘what is the statement of the theorem in the Lean code, and does this correspond to the actual theorem statement,’” explained mathematician Kevin Buzzard of Imperial College London in a blog post.
A second question was whether the Lean code would successfully compile for other mathematicians. Independent researchers, including Andrew Sutherland, a mathematician at the Massachusetts Institute of Technology, have now separately compiled Alpöge’s result in Lean without issues.
“The Lean proof has been compiled and independently rechecked by the Lean kernel with only the three standard axioms,” Sutherland says. “Honestly the chance that anything is fishy here is approximately zero.”
Researchers are still making sure that the proof does not include any hack, dodge or shortcut that changed the meaning of the initial hypothesis or any other mathematical rules or truths. This process, called a “comparator run,” typically takes a matter of hours.
“We still await a successful comparator run, which will check that (a) the code does not do anything nefarious like redefine the meaning of any of the symbols in the statement and (b) (assuming it’s run in paranoid mode) the code compiles with several independent kernels (so the code is not just exploiting an as yet unknown bug in Lean’s official kernel,” Buzzard wrote on an online chat server for the Lean community.
